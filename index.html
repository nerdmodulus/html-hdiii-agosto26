01

Qué es el HTML

HTML significa HyperText Markup Language: lenguaje de marcado de hipertexto. La palabra clave es marcado. No programas nada: tomas un texto y lo marcas para decirle al navegador qué es cada parte. «Esto es un título», «esto es un párrafo», «esto es una imagen».

El navegador lee ese archivo de texto de arriba hacia abajo, interpreta las marcas y dibuja la página en pantalla. Eso es todo lo que ocurre cuando abres cualquier sitio web.

Los tres lenguajes de una página

Casi ninguna web usa HTML sola. Trabaja junto a otros dos lenguajes, y cada uno tiene un trabajo distinto:

Reparto de tareas

  • HTML — el esqueleto. Define qué contenido hay y cómo se organiza.
  • CSS — la ropa. Define colores, tamaños, tipografías, posiciones.
  • JavaScript — los músculos. Define qué pasa cuando el usuario hace algo.

Una página puede vivir solo con HTML: se verá fea, pero funciona. Sin HTML, en cambio, no hay nada que vestir ni mover.

HTML no es un lenguaje de programación. No tiene variables, ni condiciones, ni bucles. Solo describe contenido. Por eso se aprende rápido y por eso nadie es «programador» por saber HTML, aunque sí es el primer paso de todo lo demás.

Qué pasa cuando abres un sitio

  1. Escribes una dirección y el navegador se la pide a un servidor.
  2. El servidor responde con un archivo .html: puro texto.
  3. El navegador lo lee y arma el contenido en pantalla.
  4. Si ese archivo menciona hojas CSS, imágenes o scripts, los pide también y los aplica.

El código que estás por aprender es exactamente lo que viaja en el paso 2.

02

Anatomía de una etiqueta

Una etiqueta (o tag) es una palabra encerrada entre < y >. Casi siempre vienen de a dos: una que abre y otra que cierra, con el contenido en medio. La de cierre lleva una barra.

<a href="pagina.html">Ver más</a>

Al conjunto completo —apertura, contenido y cierre— se le llama elemento. Los atributos son información extra que va siempre dentro de la etiqueta de apertura, con el formato nombre="valor".

Atributos que verás todo el tiempo

  • href — a dónde lleva un enlace.
  • src — de dónde sale una imagen o un video.
  • alt — texto alternativo que describe una imagen.
  • class e id — nombres para poder darle estilo o buscarla después.
  • style — estilo escrito directamente sobre el elemento.

Etiquetas que no se cierran

Algunas no envuelven nada, así que se escriben solas. Se llaman elementos vacíos:

<br>          salto de línea
<hr>          línea divisoria
<img src="foto.jpg" alt="Un gato">

Anidamiento: cajas dentro de cajas

Puedes meter elementos dentro de otros, pero el orden de cierre importa: lo último que abres es lo primero que cierras.

Correcto

<p>Hola <strong>a todos</strong></p>

Incorrecto

<p>Hola <strong>a todos</p></strong>

El navegador es tolerante y muchas veces adivina lo que quisiste hacer, pero no siempre acierta. Escribir bien anidado te ahorra horas de errores raros.

03

La estructura del documento

Todo archivo HTML completo tiene el mismo esqueleto. Estas cuatro piezas se repiten en absolutamente cualquier sitio que abras:

<!-- Aviso: este documento es HTML -->
<!DOCTYPE html>
<html lang="es">
  <head>
    <!-- información sobre la página, no se ve -->
    <meta charset="UTF-8">
    <title>Mi primera página</title>
  </head>
  <body>
    <!-- todo lo visible va acá -->
    <h1>Hola</h1>
  </body>
</html>
  • <!DOCTYPE html> — le avisa al navegador que use las reglas modernas. Siempre en la primera línea.
  • <html> — envuelve todo el documento. El atributo lang declara el idioma.
  • <head> — la ficha técnica: título de la pestaña, codificación de caracteres, enlaces al CSS. Nada de esto aparece en la página.
  • <body> — el contenido visible. Aquí trabajarás el 95% del tiempo.

El <meta charset="UTF-8"> no es opcional en español. Sin él, los acentos y las eñes se convierten en símbolos ilegibles: «información» se ve como «informaciÃ³n».

Los comentarios se escriben entre <!-- y -->. El navegador los ignora; sirven para dejarte notas a ti mismo o a quien edite después.

04

Etiquetas de texto

El grupo más básico. Con estas cinco ya puedes escribir un documento entero.

Títulos: de h1 a h6

Seis niveles de jerarquía, como en un informe. El h1 es el título principal y debería haber solo uno por página; los demás abren secciones y subsecciones.

Los títulos no son «texto grande». Marcan estructura. Si solo quieres letras más grandes, eso es trabajo del CSS. Los buscadores y los lectores de pantalla usan esta jerarquía para entender de qué trata tu página.

Párrafos: p

Cada bloque de texto corrido va en su propio <p>. El navegador les pone separación automática. Un error frecuente es escribir todo en un solo párrafo y separar con saltos de línea: se ve parecido, pero estructuralmente es un desastre.

Saltos y divisiones: br y hr

<br> corta la línea sin abrir un párrafo nuevo, útil en direcciones o versos. <hr> dibuja una línea que separa temas.

05

El caso b contra strong

En pantalla, <b> y <strong> se ven idénticos: negrita. Lo mismo pasa con <i> y <em>: ambos dan cursiva. Entonces, ¿por qué existen los dos pares?

Porque uno describe cómo se ve y el otro describe qué significa.

Solo apariencia

<b> pone en negrita porque sí. <i> pone en cursiva porque sí. Son instrucciones visuales sin contenido semántico: nombres científicos, términos en otro idioma, la entradilla de una nota.

Apariencia y significado

<strong> dice «esto es importante». <em> dice «esto va enfatizado». Un lector de pantalla cambia el tono de voz al leerlos; un buscador les da más peso.

La regla práctica: si el texto importa más que el resto, usa <strong>. Si solo quieres negrita por razones de diseño, usa <b> —o mejor aún, CSS—. En la duda, <strong> y <em> son la elección más segura.

Esta distinción tiene un nombre: HTML semántico. Es la idea de elegir etiquetas por lo que el contenido es, no por cómo quieres que se vea. Vuelve a aparecer en la sección 7 con <div>.

Y el span

El <span> es la etiqueta neutra: no cambia nada por sí sola. Existe para marcar un trozo de texto dentro de una frase y poder darle estilo después. Es el equivalente en línea del <div> que verás en la sección 7.

06

Bloque y en línea

Este es el concepto que explica el 80% de los «¿por qué se me descuadró todo?». Cada elemento se comporta de una de dos maneras:

De bloque

Ocupa todo el ancho disponible y empuja lo siguiente hacia abajo. Se apilan como ladrillos.

p h1–h6 div ul li table section

En línea

Ocupa solo lo que mide su contenido y convive con el texto en la misma fila.

span a strong em b i img

caja uno caja dos caja tres

Tres elementos de bloque: cada uno reclama su propia fila.

Una consecuencia práctica: no puedes meter un elemento de bloque dentro de uno en línea. Un <div> dentro de un <span> rompe el flujo; al revés funciona perfecto.

07

El div y sus reemplazos

El <div> es una caja genérica y vacía de significado. No se ve, no hace nada: solo agrupa. Sirve para juntar varios elementos y tratarlos como una unidad —moverlos, ponerles fondo, alinearlos—.

Es la etiqueta más usada de la web y también la más abusada. Un sitio hecho solo de <div> funciona, pero es ilegible: nadie —ni un buscador, ni un lector de pantalla, ni tú dentro de seis meses— sabe qué es cada caja.

Las etiquetas semánticas

Por eso HTML incorporó cajas con nombre. Se comportan exactamente igual que un <div>, pero declaran su función:

<header> — encabezado: logo, título
<nav> — menú de navegación
<main> — contenido principal, uno por página
<section> — un bloque temático
<article> — contenido con sentido propio
<aside> — contenido lateral o secundario
<footer> — pie: contacto, créditos

La regla es sencilla: usa la etiqueta semántica cuando exista una que describa lo que estás agrupando, y guarda el <div> para cuando solo necesites una caja sin más razón que acomodar el diseño.

08

Listas, enlaces e imágenes

Listas

Dos tipos: <ul> para listas sin orden (viñetas) y <ol> para listas ordenadas (números). Dentro de cualquiera de las dos, cada ítem va en un <li>.

Enlaces

El <a> es la etiqueta que hizo posible la web: convierte texto en un salto a otro lugar. Su atributo href indica el destino.

  • href="https://sitio.cl" — otra página en internet.
  • href="contacto.html" — otro archivo tuyo, en la misma carpeta.
  • href="#s8" — un punto dentro de la misma página (usa el id del destino).
  • href="mailto:hola@ejemplo.cl" — abre el correo.

Agregar target="_blank" hace que se abra en una pestaña nueva. Úsalo con criterio: solo cuando el usuario perdería algo al salir de tu página.

Imágenes

El <img> no se cierra y necesita dos atributos. src apunta al archivo; alt describe la imagen en palabras.

El alt no es opcional. Es lo que escucha una persona ciega usando lector de pantalla, lo que se muestra si la imagen no carga, y lo que lee Google. Descríbela como se la describirías a alguien por teléfono. Si la imagen es puramente decorativa, deja alt="" vacío.

09

Tablas

Una tabla se construye por filas, no por columnas. Tres etiquetas bastan:

  • <table> — la tabla completa.
  • <tr> — table row, una fila.
  • <td> — table data, una celda. Se usa <th> para las celdas de encabezado.

El navegador cuenta las celdas de cada fila para armar las columnas. Si una fila tiene una celda de menos, la tabla se descuadra.

Las tablas son para datos, no para diseño. Hasta los 2000 se maquetaban sitios completos con tablas invisibles. Hoy eso lo hace el CSS. Usa <table> solo cuando la información realmente tenga filas y columnas.

10

class, id y la puerta al CSS

Hasta aquí todo se ve con los estilos por defecto del navegador. Para cambiar eso necesitas señalar elementos, y para señalarlos hay dos atributos:

  • class — una etiqueta reutilizable. Muchos elementos pueden compartir la misma clase, y uno puede tener varias: class="destacado grande".
  • id — un nombre único. Solo un elemento en toda la página puede tener ese id. Sirve para enlaces internos y para JavaScript.

Después, el CSS los busca por nombre: un punto para las clases (.destacado) y una almohadilla para los id (#titulo).

Tres formas de aplicar estilo

  1. En línea, con el atributo style sobre el elemento. Rápido pero desordenado.
  2. Interna, con una etiqueta <style> dentro del <head>. Sirve para un archivo único.
  3. Externa, en un archivo .css aparte enlazado con <link>. Es la forma correcta en un proyecto real.

11

Cómo probar tu código

No necesitas instalar nada. Cualquier computador ya tiene lo suficiente.

  1. Abre el Bloc de notas (o TextEdit en Mac, en modo texto plano).
  2. Escribe tu HTML.
  3. Guarda el archivo como pagina.html —con esa extensión, no .txt—.
  4. Haz doble clic. Se abre en tu navegador.
  5. Edita, guarda, y recarga con F5 para ver los cambios.

Para trabajar en serio conviene un editor de código como Visual Studio Code: colorea las etiquetas, cierra las que abriste y avisa de los errores.

Leer el código de cualquier sitio

Haz clic derecho sobre cualquier página y elige Inspeccionar (o presiona F12). Se abren las herramientas de desarrollo del navegador y ahí está el HTML real del sitio. Al pasar el cursor por cada línea, el navegador ilumina la parte de la página que corresponde.

Es la mejor forma de aprender: elige un sitio que te guste y desármalo.

Hacia dónde seguir

Con esto ya puedes escribir una página completa. Los siguientes pasos naturales son:

  • CSS — el lenguaje del diseño. Es el complemento obligatorio del HTML.
  • Formularios — <form>, <input>, <select> y <button> para recibir datos del usuario.
  • Multimedia — <video>, <audio> y <iframe> para incrustar contenido externo.
  • Accesibilidad — cómo hacer que tu sitio funcione para todo el mundo. El alt y las etiquetas semánticas ya fueron tu primera lección.
